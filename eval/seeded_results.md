## How much this proves

Read the numbers below with these limits in mind.

- **The set is small.** 10 seeded errors and 2 controls. One extra failing case would move the rate by about 10 points.
- **The cases were written by the same person who wrote the rules.** They test failure modes that were already known, several taken from real failures in run 5. This measures whether the known guards fire, not whether the system is hard to fool.
- **The claim checker is not deterministic.** Two earlier single passes over this same set gave 10 of 10 and then 9 of 10, with the wrong-attribution case caught once and missed once. That is why every case is now run several times and the per-case catch count is reported instead of a single pass.
- **One fault per case, with one exception.** `E02` plants a dropped hedge, but "tidak berubah" is also an unsupported absolute, so two independent rules fire on one planted fault.
- **The controls are the weakest part.** Two clean captions cannot establish a false-positive rate. The real false-positive evidence is the pipeline run, where strict rules reject copy that reads fine.
- Both layers are evaluated on every case, including cases the code already rejects, so the claim checker's own contribution is visible rather than hidden behind the pipeline's short-circuit.
